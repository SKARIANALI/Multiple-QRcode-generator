3. QR SPLITTING RULE

Use a maximum QR amount of:

MAX_QR_AMOUNT = ₹1999

Rules:

Amount below ₹2000

Generate exactly one QR containing the entire amount.

₹100
→ 1 QR = ₹100

₹500
→ 1 QR = ₹500

₹1999
→ 1 QR = ₹1999
Amount ₹2000 or greater

Split the amount into the minimum possible number of QR codes, with every QR amount being less than ₹2000.

Examples:

₹2000
→ ₹1999 + ₹1

₹2001
→ ₹1999 + ₹2

₹4000
→ ₹1999 + ₹1999 + ₹2

₹5000
→ ₹1999 + ₹1999 + ₹1002

₹10000
→ ₹1999 + ₹1999 + ₹1999 + ₹1999 + ₹1999 + ₹5

The sum of every generated QR amount MUST exactly equal the original amount.

Do not create unnecessary QR codes.

4. MONEY PRECISION

Never use JavaScript floating-point arithmetic for financial calculations.

Represent money internally using integer paise.

Examples:

₹1 = 100 paise
₹500 = 50000 paise
₹1999 = 199900 paise
₹4000 = 400000 paise

The split algorithm must operate on integer paise.

Support up to 2 decimal places.

Example:

₹100.50

The maximum QR limit is:

199900 paise
5. QR SPLIT FUNCTION

Create a reusable utility:

splitAmount(amountInPaise: number): number[]

Algorithm:

remaining = amountInPaise

while remaining > 0:

    qrAmount = min(remaining, 199900)

    add qrAmount to result

    remaining -= qrAmount

Example:

400000
→ 199900
→ 199900
→ 200

Display:

₹1999
₹1999
₹2

The function must be pure and unit-testable.

6. UPI QR GENERATION

Generate a UPI payment URI for every QR.

Example:

upi://pay?pa=shop@upi&pn=ABC%20Store&am=1999.00&cu=INR&tn=Payment

Include:

pa = receiver UPI ID
pn = receiver name
am = exact QR amount
cu = INR
tn = payment note

Correctly URL-encode all parameters.

Each QR must contain its own exact amount.

For ₹4000:

QR 1 → amount = 1999
QR 2 → amount = 1999
QR 3 → amount = 2

Do not put API keys, passwords, UPI PINs, or secrets into the QR.

Do not claim that the UPI ID has been verified merely because it passes syntax validation.
